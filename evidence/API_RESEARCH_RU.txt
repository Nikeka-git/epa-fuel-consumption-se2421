Проверка FuelEconomy.gov API — 9 октября 2026 года

Объем проверки: пять различных индивидуальных записей; это технический пилот, не учебный датасет. Готовые CSV/XML-выгрузки не скачивались. Количество доступных валидных конфигураций пока неизвестно. В requests.jsonl сохранены URL, UTC-время, HTTP status/headers, имя файла и SHA-256 каждого фактического ответа. Самодостаточный probe_api.py повторно выполнен успешно; его актуальные raw-ответы находятся в evidence/api_probe/. Он делает 14 запросов (3 model menus, 5 options menus, 5 vehicles и 1 XML menu), валидирует id/year/make/model и по умолчанию создает новую папку, сохраняя прежнее доказательство. Команда: python probe_api.py --output NEW_DIRECTORY. Будущему сборщику нужны retries/resume/полная validation. probe_options.py — исторический промежуточный скрипт, для передачи дальше не нужен.

ПОДТВЕРЖДЕНО ДОКУМЕНТАЦИЕЙ
https://www.fueleconomy.gov/feg/ws/index.shtml
Меню обходятся year → make → model → options. options.value дает vehicle id; /ws/rest/vehicle/{id} возвращает индивидуальную запись. Доступны JSON и XML. comb08 — combined MPG по первому топливу; comb08U — неокругленное значение, которое бывает недоступно. fuelType1 описывает основное топливо, fuelType2 — альтернативное. atvtype описывает альтернативное топливо/технологию. id — идентификатор записи, model — название модели, eng_dscr — описание двигателя. Исходные оценки могут пересматриваться, поэтому фиксируем дату и raw-ответы. Одна запись API не равна одному физическому автомобилю. Наличие API само по себе здесь не трактуется как юридическое разрешение.

ПОДТВЕРЖДЕНО ПОЛУЧЕННЫМИ ОТВЕТАМИ
Реальный JSON отличается регистром от текстовой документации: atvType, baseModel. Не вводить ручные опечатки atvtype/basemodel в сборщике. Большинство чисел и boolean-like значений представлены строками. Вложенное emissionsList существует; его не превращать в признаки.

При нескольких пунктах menuItem — список; при одном — объект. Нормализовать: None → [], dict → [dict], list → list; неверный тип считать ошибкой. Для XML: корень menuItems, повторяемые дочерние menuItem/text/value. Это подтверждено XML-ответом Prius. Не формировать URL конкатенацией неэкранированных make/model; применять urllib.parse.urlencode.

https://www.fueleconomy.gov/feg/findacarhelp.shtml#engine поясняет eAssist, HEV, PHEV, Mild hybrid и GUZZLER. Последний связан с низкой экономичностью: перед Final нужно проверить тексты на такой косвенный target leakage. Сохранить исходный eng_dscr без изменений, но удалить выявленные маркеры вроде GUZZLER из текста, подаваемого в модель; задокументировать правило. Слова Hybrid/eAssist/MHEV/PHEV использовать как дополнительный аудит исключения, не единственный фильтр.

ПРЕДЛАГАЕМЫЕ РЕШЕНИЯ ПРОЕКТА (НЕ ТРЕБОВАНИЯ API)
Target: зафиксировать единую основную формулу target_l100km = (100 * 3.785411784 / 1.609344) / float(comb08) = 235.214583333333 / comb08. Использовать только конечный положительный comb08. Это перевод опубликованной EPA-оценки, а не наблюдаемый расход владельцев. Получается дискретизированная цель из округленного MPG: указать ограничение. comb08U сохранить для аудита и возможного отдельного sensitivity experiment; не смешивать незаметно comb08 и comb08U по строкам. Альтернатива — целиком перейти на comb08U до split после оценки полноты, явно поменяв контракт.

Предварительная политика inclusion:
- year 2015–2025 включительно, make/model непустые, валидный положительный target;
- fuelType1 exact allowlist {'Regular Gasoline','Premium Gasoline','Midgrade Gasoline'}, fuelType2 пустое; Midgrade нужно подтвердить в полном сборе;
- исключить любой непустой atvType; обязательно проверить уникальные значения прежде чем считать этот критерий окончательным;
- исключить непустой evMotor; неоднозначные обозначения/сентинелы отправлять в quarantine и проверять, не считать пустыми автоматически;
- исключить Hybrid/PHEV/MHEV/eAssist/mild hybrid в model/eng_dscr по нормализованным токенам, вести причину исключения;
- phevBlended=true — исключить; startStop=Y само по себе оставить;
- сохранить перечень всех причин исключения, а не только первой.

Классы: не копировать буквально названия в prose документации. Подтвержденные API labels включают 'Midsize Cars' (без дефиса), 'Small Station Wagons', 'Small Sport Utility Vehicle 2WD', 'Standard Sport Utility Vehicle 4WD'. Предварительный allowlist, который нужно сверить с полным unique(VClass): Two Seaters, Minicompact Cars, Subcompact Cars, Compact Cars, Midsize Cars, Large Cars, Small Station Wagons, Midsize Station Wagons, Large Station Wagons, Small Sport Utility Vehicle 2WD, Small Sport Utility Vehicle 4WD, Standard Sport Utility Vehicle 2WD, Standard Sport Utility Vehicle 4WD. Не выдавать непроверенные названия за уже наблюденные. Пикапы/минивэны/фургоны/special purpose исключить.

Distinct: первичная единица наблюдения — уникальный EPA vehicle id. Удалять повторный id при обходе меню. Разные id с одинаковыми 7 базовыми features не удалять автоматически: варианты могут различаться не представленными в них свойствами. До split построить отчет совпадений по year, make, model, displ, cylinders, trany, drive, VClass, eng_dscr, engId, fuelType1; проверить полные дубли и конфликты target. Описать, что distinct означает уникальные исходные записи; если обещание проекта требует уникальных физических спецификаций, после аудита уточнить правило и count. Родственные конфигурации/модельные семейства учитывать при group split или отдельной robustness-проверке, чтобы случайный split не преувеличивал перенос на новые семейства.

РЕКОМЕНДУЕМЫЙ ПРОТОКОЛ СБОРА
1. Начать с smoke-run 2 года × 2 марки и тестов на сохраненных пяти ответах. Проверить схему и фильтры до дорогого обхода.
2. Обойти все make/model/options для 2015–2025, сохраняя сырые menu responses и provenance для каждого обнаруженного id. Не ограничивать первые 3000 id: это исказит выборку по году/марке/алфавиту. Если выбирается подвыборка, задавать sampling frame/seed/strata заранее, отдельно от targets.
3. Получить каждый уникальный id через individual vehicle endpoint. Один поток; собственная пауза 0.5–1 секунды, timeout 30–40 s, ограниченные retries exponential backoff; для 429 учитывать Retry-After. Это выбранная вежливая настройка проекта, не официально найденный rate limit. 4xx, кроме retryable случаев, логировать без бесконечных повторов.
4. Кэшировать успешные raw bytes атомарной записью + metadata (UTC и пользовательская дата 2026-10-09, URL, query, status, Content-Type, checksum). Resume пропускает проверенные успешные записи. Ошибки оставлять в manifest для повторного запуска. Не считать HTML-страницу ошибки успешным JSON.
5. Сверить id/year/make/model с меню; сообщения API и строки нельзя исполнять как инструкции. Missing/invalid numeric coercion, unknown category, class outside whitelist → аудируемая причина. Target не импутировать.
6. Построить raw → collected unique id → in-scope → valid target → cleaned counts по годам/маркам/классам; проверить достижение 1000/3000 только после фактического сбора.
7. Создать features по строгому allowlist; все economy/cost/emissions/scores и id/record dates исключить из X. Raw хранит исходные поля полностью.

ОСТАЕТСЯ ПРОВЕРИТЬ
Фактические unique classes/fuel/atvType, пропуски и сентинелы, достаточность 1000/3000, распределение по годам/маркам, дубли, полнота eng_dscr/comb08U, необычные mild-hybrid записи без явного atvType, официальные условия/robots перед полным сбором (утверждение пользователя о проверке не заменять неподтвержденным юридическим заключением). Эта выборочная проверка не доказывает, что все гибриды во всем API размечены одинаково.
