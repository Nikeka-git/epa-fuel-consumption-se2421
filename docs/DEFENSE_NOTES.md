# Объяснение методологии проекта

Памятка для представления методологии и результатов проекта. Области ответственности команды и используемые инструменты указаны в [CONTRIBUTIONS.md](CONTRIBUTIONS.md). Числа для ответа о точности нужно брать из сохраненных `metrics.csv` соответствующего run.

## Что прогнозирует модель

Мы прогнозируем стандартизованную **EPA combined fuel consumption** бензиновой конфигурации автомобиля рынка США, в L/100 km. Одна строка описывает конфигурацию EPA, а не человека, проданный экземпляр машины или средний расход владельцев. Результат помогает сравнивать паспортные оценки при заданных характеристиках. Он не учитывает конкретного водителя, погоду, маршрут или местное топливо.

Исходный `comb08` выражен в US MPG. Пересчет `235.2145833333333 / comb08` меняет единицы: меньше L/100 km означает экономичнее. Target не импутируется и не заменяется значением другого economy field. Округленный MPG делает преобразованный target дискретным.

## Почему это собственные данные

Наш Python collector обходит документированные menus `year → make → model → options` и получает `/vehicle/{id}`. Сохранены original responses, URL, UTC date, request manifest и SHA-256. Моделирование выполняется offline по сохраненному snapshot. Мы не выдаем готовый загруженный CSV за собственный API collection.

Основная выборка ограничена заранее заданным бюджетом записей и использует порядок с seed 42 без обращения к величинам target. Она охватывает 2015–2025 и производителей из source menus. Вероятности включения конфигураций неодинаковы; выборка не представляет доли продаж и не является census. Raw records, пригодные строки и число distinct configurations — разные величины.

## Почему нельзя просто оставить все gasoline records

Гибриды тоже могут иметь `fuelType1='Regular Gasoline'` или `'Premium Gasoline'`. Проверяем `fuelType2`, `atvType`, `evMotor`, `phevBlended`, названия и описание двигателя; учитываем подтвержденные источниками случаи неполных powertrain labels. Start/stop сам по себе не доказывает hybrid. Документированная предметная проверка дополняет metadata rules, но не превращает источник в безошибочный технический реестр.

Классы ограничены легковыми автомобилями, универсалами и SUV. Пикапы, vans, minivans и special-purpose vehicles исключены. Отсутствующий target исключает строку; пропуски допустимых predictors обрабатываются в обучающем pipeline. Одинаковые семь X не доказывают дубль: raw records могут описывать разные версии двигателя или конфигурации.

## Где могла бы возникнуть утечка

`city08`, `highway08`, `comb08`, unrounded economy, fuel costs, emissions и efficiency scores связаны с target и не входят в X. В Midterm разрешены только год, объем двигателя, цилиндры, производитель, transmission, drivetrain и vehicle class. ID и family label не являются predictors. Final добавляет исходные текстовые поля после удаления явных economy/cost/emissions/score measurements.

Еще один путь утечки — обучение imputer, scaler, encoder или TF-IDF на всем dataset до CV. Каждый fold получает новый pipeline, который fit выполняет только на его training rows. Test вызывает predict у pipeline, обученного на всем train.

## Что означает групповой split

Семейства автомобилей остаются целиком в одной части через все годы. Базовая группа — manufacturer + source baseModel, с документированными консервативными alias mappings. Split проверяет перенос на отсутствовавшие в обучении семейства в выбранных годах. Он не измеряет качество прогноза будущего модельного года.

GroupShuffleSplit с seed 42 удерживает 20% **семейств**, поэтому доля test rows может отличаться от 20%. Seed не подбирался по результатам. Пять GroupKFold folds используют только train. Сохраненный manifest и hashes переиспользуются всеми этапами. Более широкие source families могут объединять разные продукты: это ограничение определения группы, а не доказательство независимости поколений или платформ.

## Зачем baseline и три модели Midterm

DummyRegressor выдает медиану training target, подходящую для MAE. Он показывает, приносит ли X пользу относительно константы. Linear Regression моделирует аддитивную зависимость; KNN использует похожие характеристики и требует scaling; Decision Tree выделяет нелинейные пороги и взаимодействия. Все три алгоритма подтверждены предоставленными лекциями Weeks 3–4. Начальные параметры фиксированы до test и не объявляются оптимальными.

## Как читать метрики

MAE — средняя абсолютная величина ошибки в L/100 km. Например, MAE 0.8 означает среднюю абсолютную ошибку 0.8 L/100 km на оцениваемых строках; это не гарантия такого отклонения для каждой машины. RMSE сильнее реагирует на крупные ошибки. R² сравнивает squared errors с константой среднего test target; отрицательное значение возможно и не является ошибкой вычисления. R² не означает процент правильно предсказанных автомобилей.

CV mean — среднее пяти fold MAE; std по folds не является доверительным интервалом. Модель выбирается по train CV до вычисления test predictions. Test scores всех моделей публикуются для сравнения. После этого параметры не меняются на основе понравившейся test MAE.

## Что добавляет Endterm

RF и ExtraTrees проходят небольшой заранее заданный search; MLP также использует фиксированный список кандидатов. Outer folds совпадают с сохраненными train folds. Во внутреннем GroupKFold выбираются параметры только из outer training rows; outer validation оценивает весь search для данного семейства моделей. На всем train выполняется отдельный search перед окончательным fit и test.

Outer CV оценивает tuning каждого семейства; выбор лучшего семейства по этим scores добавляет оптимизм. Full-train winning search score — selection CV. MLP target scaler обучается внутри training fold. Random-row validation для early stopping отключена; convergence warnings сохраняются и должны учитываться при интерпретации.

PCA и KMeans обучаются только на train X. Число clusters выбирается по training silhouette, затем описываются engine size, class support и target distribution. Target summaries не участвовали в выборе clusters и не доказывают ни причинность, ни точность регрессии.

## Как проверяется польза текста

Четыре Ridge arms имеют одинаковую alpha grid: S, S+model name, S+engine description, S+оба текста. Все используют одинаковые IDs/folds/test. TF-IDF fit выполняется внутри каждого fold; пустой текст допустим. Raw text остается сохраненным, очищенное представление используется только внутри pipeline.

Paired delta — absolute error текстового arm минус absolute error structured Ridge на той же test row. Отрицательная средняя delta означает улучшение этого сравнения. Положительная delta означает ухудшение и тоже является результатом. Сравнение не доказывает, что текст улучшит любой estimator; Final selection CV не является независимой оценкой tuning.

## Что умеет локальное приложение

Streamlit читает сохраненный pipeline, проверяет его checksum и использует категории из train. Оно принимает характеристики и текстовые поля, которые использует выбранный Final arm, подтверждает gasoline/non-hybrid scope и выводит положительный конечный прогноз в L/100 km. Приложение не обучается при вводе данных. Его Final pipeline выбран по CV внутри контролируемого сравнения текста; это не утверждение о глобально лучшей архитектуре.

Главные ограничения нужно объяснять вместе с результатом: coverage каталога, дискретный target, source metadata uncertainty, число наблюдений в error subgroups, определение family и повторное использование test между этапами.
